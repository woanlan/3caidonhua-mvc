CẨM NANG VẤN ĐÁP BẢO VỆ MÔN HỌC

Tổng hợp trọn bộ câu hỏi lý thuyết, luồng MVC, cơ sở dữ liệu MongoDB và giải thích từng dòng code Controller

🔍
CÂU 01 Em hãy giải thích mô hình MVC trong dự án này?
▼
Dạ thưa cô, dự án áp dụng mô hình kiến trúc MVC phân tách rõ ràng:
• Model (`models/`): Định nghĩa Schema và tương tác trực tiếp với cơ sở dữ liệu MongoDB thông qua Mongoose ODM.
• Controller (`controllers/`): Xử lý toàn bộ logic nghiệp vụ. Mỗi hàm nhận 2 đối số là (req, res), gọi Model để lấy/lưu dữ liệu và dùng res.status(...).json(...) để trả kết quả về client.
• Route (`routes/`): Chỉ làm nhiệm vụ điều hướng URL và phương thức HTTP (GET, POST, PUT, DELETE) vào đúng hàm trong Controller.
• View (`views/` & `public/`): Giao diện người dùng SPA (Single Page Application) nhận dữ liệu JSON từ API và render mượt mà.
CÂU 02 Vòng đời của 1 Request (Request Lifecycle) từ Frontend đến Database?
▼
Luồng đi của 1 request ví dụ `GET /api/categories`:
1. Trình duyệt gửi HTTP GET request đến Server Node.js.
2. Request đi qua `app.js` và các middleware toàn cục (cors, json, cookieParser).
3. `app.js` chuyển giao cho file `routes/categories.js`. Khớp với route `/` gọi hàm `CategoryController.getAll`.
4. `CategoryController.getAll` gọi `categoryModel.find()` để truy vấn MongoDB.
5. MongoDB trả kết quả về cho Controller.
6. Controller đóng gói kết quả và gọi return res.status(200).json(categories) trả về cho trình duyệt.
CÂU 03 Khóa ngoại trong Mongoose là gì? Phương thức `.populate()` hoạt động thế nào?
▼
Trong Mongoose, khóa ngoại được tạo bằng cách khai báo trường có kiểu type: ObjectId kèm thuộc tính ref: 'tên_model'.
• Tác dụng của `.populate()`: Hoạt động tương tự câu lệnh JOIN trong SQL. Mongoose sẽ tự động lấy ObjectId của trường đó, tìm sang collection được tham chiếu và thay thế trường đó bằng toàn bộ thông tin chi tiết (ví dụ lấy tên danh mục thay vì chỉ hiện mã ID thô).
// Ví dụ trong ProductController.js:
const products = await productModel.find().populate('category');
CÂU 04 Tại sao tất cả các hàm Controller đều dùng `async / await`? Nếu bỏ `await` thì sao?
▼
• Lý do: Các thao tác đọc/ghi cơ sở dữ liệu qua Mongoose đều là tác vụ Bất đồng bộ (Asynchronous) cần thời gian xử lý qua mạng và trả về một Promise.
• Từ khóa `await`: Yêu cầu Node.js tạm dừng để đợi MongoDB xử lý xong và trả dữ liệu về rồi mới thực thi tiếp các dòng bên dưới.
• Nếu bỏ `await`: Biến nhận dữ liệu sẽ chỉ là Promise { <pending> } chưa có dữ liệu, dẫn đến gửi mảng rỗng về cho client hoặc gây lỗi ứng dụng.
CÂU 05 Giải thích từng dòng code của hàm `CategoryController.getAll`?
▼
getAll: async (req, res) => {
  try {
    // 1. Tìm tất cả danh mục trong MongoDB, sắp xếp theo thứ tự hiển thị và ngày tạo
    // .lean() để trả về plain JS object giúp bổ sung trường productCount dễ dàng
    const categories = await categoryModel.find().sort({ order: 1, createdAt: 1 }).lean();

    // 2. Đếm số lượng sản phẩm thực tế thuộc từng danh mục
    for (const c of categories) {
      c.id = c._id.toString();
      c.productCount = await productModel.countDocuments({
        $or: [{ category: c._id }, { categoryId: c._id }]
      });
    }

    // 3. Trả về mã 200 (Thành công) cùng danh sách dữ liệu dạng JSON
    return res.status(200).json(categories);
  } catch (err) {
    // 4. Bắt lỗi nếu có sự cố DB và trả về mã lỗi 500
    return res.status(500).json({ message: err.message });
  }
}
CÂU 06 Tại sao trong `CategoryController.remove` không xóa luôn mà phải kiểm tra `countDocuments`?
▼
Đây là nghiệp vụ bảo toàn toàn vẹn dữ liệu (Data Integrity):
Nếu xóa một danh mục đang có chứa sản phẩm, tất cả các sản phẩm đó sẽ bị mồ côi (không còn liên kết với danh mục nào). Do đó em kiểm tra:
const productCount = await productModel.countDocuments({ category: id });
if (productCount > 0) return res.status(400).json({ message: 'Chặn xóa: Danh mục còn sản phẩm' });
Chỉ khi nào productCount === 0 thì hệ thống mới cho phép xóa bằng findByIdAndDelete(id).
CÂU 07 Phân biệt `req.params`, `req.body`, `req.query`, `req.cookies`?
▼
• `req.params`: Lấy biến trên URL qua dấu hai chấm (vd: /products/:id ➔ req.params.id).
• `req.body`: Lấy dữ liệu gửi trong thân gói tin HTTP (dùng trong POST/PUT khi gửi form hoặc JSON).
• `req.query`: Lấy tham số sau dấu hỏi ? trên URL (vd: /products?grade=RG&sort=asc ➔ req.query.grade).
• `req.cookies`: Đọc thông tin phiên đăng nhập lưu trong cookie trình duyệt (vd: req.cookies.userId).
CÂU 08 Ý nghĩa các mã HTTP Status Code: 200, 201, 400, 401, 403, 404, 500?
▼
• 200 OK: Thành công chung (Lấy dữ liệu, cập nhật thành công).
• 201 Created: Tạo mới thành công (Thêm sản phẩm, tạo đơn hàng).
• 400 Bad Request: Dữ liệu gửi lên sai hoặc thiếu (Tên quá ngắn, giá âm).
• 401 Unauthorized: Chưa đăng nhập hoặc sai mật khẩu.
• 403 Forbidden: Bị cấm truy cập (Tài khoản đang bị khóa).
• 404 Not Found: Không tìm thấy bản ghi theo ID.
• 500 Internal Server Error: Lỗi hệ thống hoặc lỗi cơ sở dữ liệu trong khối `catch`.
CÂU 09 Quy trình trừ tồn kho khi mua hàng và hoàn kho khi hủy đơn trong `BillController`?
▼
• Khi đặt hàng (`create`):
Kiểm tra prod.quantity < item.quantity. Nếu đủ hàng thì lưu đơn và trừ kho an toàn bằng toán tử nguyên tử của MongoDB:
await productModel.findByIdAndUpdate(prod._id, { $inc: { quantity: -item.quantity } });
• Khi hủy đơn (`cancel`):
Duyệt qua các sản phẩm trong đơn và hoàn trả lại kho:
await productModel.findByIdAndUpdate(d.product, { $inc: { quantity: +d.quantity } });
CÂU 10 Tại sao khi lấy danh sách user em lại dùng `.select('-password')`?
▼
Dấu trừ - trong Mongoose mang ý nghĩa loại trừ trường dữ liệu khỏi kết quả truy vấn. Mật khẩu là thông tin nhạy cảm tuyệt đối, do đó .select('-password') đảm bảo mật khẩu không bao giờ bị lộ ra mạng hoặc truyền về phía giao diện người dùng.
